# RiskManagement Module Playbook

Phase 4 domain-modernization pass, second module. Status as of 2026-07-29.

## Domain model

Single aggregate root: `Risk` (`PlantSafety.Domain.RiskManagement.Aggregates.Risk`), covering the real 3-phase Full Risk Management Process:

- **Phase 1 (Assessment):** Identified → Scored (`ScoreRisk`) → Prioritized (`Prioritize`, P1-P4)
- **Phase 2 (Control):** ControlsInProgress (`ApplyControlMeasure`, Hierarchy-of-Controls) → Mitigated/ControlsInProgress (`ValidateEffectiveness`, residual-risk acceptability)
- **Phase 3 (Monitoring):** UnderReview (`StartReviewCycle`) → Mitigated (`CompleteReview`) → Closed (`Close`)

Guarded status transitions throughout (`RiskInvalidStatusTransitionException`), a `ControlMeasure` child entity collection, and a `RiskScore` value object. Already a rich aggregate going into this pass — same maturity tier as PermitToWork, not an anemic model.

Note: `PlantSafety.Domain.RiskManagement` (this module) is distinct from `PlantSafety.Infrastructure.OperationalSafety.RiskManagement`, a separate, much older, stub-level module (2 methods, no aggregate, no events) under a different SQL schema (`[OperationalSafety]` vs `[RiskMgmt]`) — do not confuse the two when doing further Phase 4 passes.

## Commands

7 lifecycle-transition commands (`ScoreRiskCommand`, `PrioritizeRiskCommand`, `ApplyRiskControlMeasureCommand`, `ValidateRiskEffectivenessCommand`, `StartRiskReviewCycleCommand`, `CompleteRiskReviewCommand`, `CloseRiskCommand`) plus `CreateRiskCommand`. All 7 mutating commands now implement `IConcurrencyAwareCommand` and carry an `ETag` (added this pass — previously none did).

## Queries

**Closed this pass:** `GetRiskByIdQuery` / `RiskItemDto` / `GetRiskByIdQueryHandler` now exist under `PlantSafety.Application.RiskManagement.{Queries,Models,Handlers}`, backed by a dedicated read-side repository (`PlantSafety.Application.RiskManagement.Repositories.IRiskRepository` — same simple name as, but a different namespace from, the write-side `PlantSafety.Domain.RiskManagement.Interfaces.IRiskRepository`, mirroring `IPermitWorkflowRepository`'s established read/write split). Exposed as `GET /api/v1/riskmanagement/{riskId}` returning `RiskItemDto` (including `ETag`) or 404.

Implementation notes / deviations from the original fix spec, and why:
- **No new stored procedure.** The spec called for a new `usp_Risk_Get`, but `usp_Risk_GetById` already did exactly that (single row, `RowVersion`→`ETag` projection, no side effects) — it just lacked TRY/CATCH+ErrorLog. Added that instead of duplicating the proc, avoiding two procs doing the same read.
- **Read repository reuses the existing proc** rather than adding a parallel one, mirroring `PermitWorkflowReadDapperRepository`'s precedent (this codebase's dominant CQRS-read convention) rather than Incident's older dedicated-read-proc convention.
- **Tenant isolation added in the handler**, not the SQL: `usp_Risk_GetById` filters only by `RiskId`/`IsDeleted`, not `TenantId` — a pre-existing gap shared with the write path (see below). The new handler treats a cross-tenant `TenantId` mismatch as `NotFound` rather than leaking existence, but this is a narrower fix than closing the gap at the SQL layer.
- **`ErrorSeverity.NotFound` used explicitly** — `ApplicationError`'s default severity is `Error` (→500), not `NotFound` (→404). The pre-existing 7 command handlers' `"RiskManagement.Risk.NotFound"` errors omit the severity argument and therefore currently return 500, not 404, on a missing risk. Not fixed here (out of scope for adding a query), but flagged below since it's a real bug hiding in code this pass touched directly.

## Events

`RiskCreatedEvent`, `RiskArchivedEvent`, and the `RiskAssessmentEvents.cs` set (scoring/prioritization/control/validation/review/close events per phase).

**Fixed in this pass (as part of a platform-wide sweep, not module-specific):** `RiskDapperRepository.UpdateAsync` never enqueued domain events to the outbox — identical bug to PermitToWork's, and confirmed present in 54 other repositories across the codebase (all generated by the same codegen tool). Fixed everywhere in one pass; see the platform-wide fix note below.

## Stored procedures / repository

`RiskDapperRepository` under `PlantSafety.Infrastructure.RiskManagement.Persistence`, backed by `usp_Risk_{Insert,Update,GetById,GetAllActive}` + `usp_ControlMeasure_{Upsert,GetByRiskId}` in the `[RiskMgmt]` schema.

**Notable: the SQL/schema side of ETag concurrency was already half-built** by an earlier "Migration Commander Phase 3" pass (2026-07-28) — the `Risk` table already had a native `RowVersion ROWVERSION` column, and `usp_Risk_GetById`/`GetAllActive` already projected it as `ETag`. That earlier pass explicitly deferred wiring it into `usp_Risk_Update`, `IRiskRepository`, and the C# write path (documented in its own comments as "schema-only"). This pass completed that wiring: `usp_Risk_Update` gained the `@ETag` guard (mirroring `usp_PermitWorkflow_Update`/`usp_Incident_Update`), `IRiskRepository.UpdateAsync` gained the `eTag` parameter, and `RiskDapperRepository.UpdateAsync` now calls it via `ExecuteScalarAsync` and throws `ConcurrencyConflictException` on zero rows affected.

## API

`RiskManagementV1Controller` — thin MediatR dispatcher, already versioned/policy-authorized. Two endpoints (`start-review`, `close`) previously took no request body at all; added `StartRiskReviewCycleRequest`/`CloseRiskRequest` (both optional-body, ETag-only) so those commands can carry a concurrency token too. All 7 mutating request DTOs now carry `ETag`.

**Fixed in this pass (platform-wide, applies here too):** `ExceptionHandlingMiddleware` previously returned a blanket HTTP 500 for every unhandled exception, even though `ConcurrencyConflictException` documented HTTP 409 in its own XML comments. Fixed during the PermitToWork pass; RiskManagement's newly-wired `ConcurrencyConflictException` now benefits from that fix automatically. The 7 RiskManagement handlers also had the same blanket `catch (Exception)` that would have swallowed a concurrency conflict into a generic 400 before it reached the middleware — added `catch (ConcurrencyConflictException) { throw; }` ahead of the generic catch in each, matching PermitToWork's fix.

## Platform-wide fix applied during this module's work

While auditing RiskManagement, the outbox-drop bug found in PermitToWork was confirmed to exist identically in 54 other repository files across nearly every module in the codebase (all authored by the same codegen tool). Rather than rediscover it module-by-module, all 54 were fixed in one pass — see git history / the corresponding session for the full file list. This is why RiskManagement's `UpdateAsync` outbox fix wasn't done by hand in this module's own pass; it was covered by that sweep, then verified.

## Cross-tenant access and NotFound-severity fixes (closed)

Both gaps flagged above were closed in a follow-up pass the same day:

- **Tenant isolation pushed to the DB boundary.** `usp_Risk_GetById`, `usp_Risk_GetAllActive`, and `usp_Risk_Update` all gained a required `@TenantId` parameter and `AND TenantId = @TenantId` in their `WHERE` clauses — a cross-tenant `RiskId` now returns/affects zero rows at the SQL layer itself, not just via an application-layer check after the fact. `IRiskRepository.GetByIdAsync`/`ListAsync` (both the Domain write-side interface and the new Application read-side interface) now require an explicit `tenantId` parameter; `UpdateAsync` needed no interface change since `RiskDapperRepository` now binds `@TenantId` from the aggregate's own `TenantId` (which is only ever set via a tenant-checked `GetByIdAsync`), mirroring `IIncidentRepository.UpdateAsync`'s identical approach. `usp_Risk_GetAllActive` was fixed too even though `ListAsync` currently has no callers — an unscoped "return every tenant's Risks" proc is a live landmine for whenever it does get wired up.
- **NotFound severity fixed.** All 7 lifecycle command handlers now pass `ErrorSeverity.NotFound` explicitly on their `"RiskManagement.Risk.NotFound"` errors, so a missing Risk correctly returns 404 instead of the previous accidental 500 (`ApplicationError`'s default severity is `Error` → 500 when omitted).
- **Tests added:** `PlantSafety.Tests/Api/Common/ResultResponseExtensionsTests.cs` — generic coverage of `ToActionResult`'s `ErrorSeverity`→HTTP-status mapping (not Risk-specific, since this is shared chokepoint infrastructure used by every module); the 2 pre-existing "NotFound" tests in `RiskAssessmentCommandHandlersTests.cs` now also assert `ErrorSeverity.NotFound`; `GetRiskByIdQueryHandlerTests.cs`'s cross-tenant test now simulates the repository the way SQL actually behaves (no row returned for a mismatched tenant) rather than relying on an app-layer post-check.
- Full suite verified green after these fixes: 741/741 unit tests passing.

**Still not done:** no `PlantSafety.DataIntegrationTests`/`PlantSafety.IntegrationTests` coverage exercising the actual stored procedures against a live SQL Server (this session has none available) — the SQL-layer tenant filtering is verified by reading the procs, not by an executed integration test.

- No `PlantSafety.IntegrationTests`/`PlantSafety.DataIntegrationTests` coverage for this module.
- The 11 unrelated "category" read-only features under `PlantSafety.Application.RiskManagement.*` (ChemicalEnvironmentalSafety, LotoConfinedSpaces, etc.) were not audited this pass — they appear to be a separate generation pass and may or may not need their own Phase 4 treatment. They likely have the same tenant-isolation question and are worth checking.
