PLANTSAFETY CROSS DOMAIN DESIGN &amp; ARCHITECTURAL MANUAL Enterprise Cross Domain Integration Architecture Extended Edition — Version 1.0 TITLE PAGE PlantSafety Platform Cross Domain Design &amp; Architectural Manual Enterprise Reference Architecture for External System Integration Extended Edition — Version 1.0 Prepared for: Enterprise Architecture Board (EAB) Integration Review Council (IRC) Platform Engineering Cross Domain Integration Teams Prepared by: PlantSafety Architecture Office PREFACE The Role of Cross Domain Systems in the PlantSafety Ecosystem PlantSafety is not an isolated safety application. It is a platform — a governed, event driven, multi module ecosystem that depends on external enterprise systems for identity, asset metadata, inventory, training records, maintenance schedules, and organizational structure. These external systems — HRIS, ERP, CMMS, LMS, MES, Supplier Management, and others — are collectively known as Cross Domain Systems . This manual defines: The architecture of cross domain integration The design principles that govern external data flows The patterns used to synchronize reference data The rules that ensure safety logic remains internal The boundaries that prevent external systems from influencing workflows The security model that protects tenant isolation The lifecycle of cross domain data This is not a functional manual. It is an architectural manual — the blueprint for how PlantSafety interacts with the enterprise ecosystem. EXECUTIVE SUMMARY Cross Domain Systems Provide Data, Not Behavior PlantSafety’s cross domain architecture is built on three foundational truths: 1. Cross Domain Systems Are Providers, Not Participants External systems supply reference data , including: Employees Machines WorkCenters Inventory Training completions Maintenance schedules Supplier qualifications They do not : Participate in workflows Consume internal events Own safety logic Trigger safety actions PlantSafety owns all safety behavior. 2. All Cross Domain Data Flows Through the Integration Hub No module connects directly to: HRIS ERP CMMS LMS MES Supplier systems The Integration Hub provides: Schema normalization Versioning Validation Rate limiting Retry logic Security enforcement Tenant isolation 3. Cross Domain Data Must Be Deterministic, Idempotent, and Traceable Cross domain data must: Be replayable Be versioned Include metadata Include source system identifiers Include timestamps Include correlation IDs This ensures: Auditability Forensic analysis Historical reconstruction Compliance reporting CHAPTER 1 — CROSS DOMAIN ARCHITECTURAL PRINCIPLES 1.1 Principle 1 — External Systems Provide Identity, Not Logic Cross domain systems provide: Who What Where When PlantSafety determines: Why How What happens next 1.2 Principle 2 — Cross Domain Data Is Reference Data Reference data is: Read only Versioned Cached Validated Non authoritative for safety logic 1.3 Principle 3 — Cross Domain Systems Must Not Influence Workflows Forbidden: HRIS triggering incidents ERP triggering alerts CMMS triggering emergency response LMS triggering compliance workflows PlantSafety owns all workflow triggers. 1.4 Principle 4 — Cross Domain Data Must Be Normalized Normalization includes: Canonical schemas Field mapping Type coercion Metadata injection Version negotiation 1.5 Principle 5 — Cross Domain Data Must Be Idempotent Repeated syncs must not: Duplicate employees Duplicate machines Duplicate training records CHAPTER 2 — CROSS DOMAIN SYSTEMS OVERVIEW This chapter defines each cross domain system and its architectural role. 2.1 HRIS (Human Resources Information System) Role: Identity provider Provides: Employees Certifications Departments Roles Employment status Consumed by: Incidents Permits Training Compliance Alerts Culture 2.2 ERP (Enterprise Resource Planning) Role: Inventory &amp; Architectural Manual A Access Token A credential used by external systems to authenticate to the Integration Hub. Adapter (Cross Domain Adapter) A translation layer that converts external system data into canonical PlantSafety schemas. AggregateId The unique identifier of the entity associated with a cross domain record (e.g., EmployeeId , MachineId ). API Contract (External) The documented shape, fields, and rules of an external system’s API. B Backfill Sync A one time or periodic operation that loads historical data from an external system. Batch ETL A scheduled extraction of large volumes of external data, transformed and loaded into PlantSafety. Boundary System Any external system that provides reference data but does not participate in PlantSafety workflows. C Canonical Schema The normalized, versioned schema used by PlantSafety to represent external data consistently. Change Notification (External) A vendor provided mechanism that alerts PlantSafety to schema or API changes. CMMS (Computerized Maintenance Management System) External system providing machine, maintenance, and asset data. Compliance Data Cross domain data required for regulatory reporting (e.g., training completions). Cross Domain Drift Any deviation between expected external data and actual incoming data. Cross Domain Freeze Window A period during which no cross domain changes may be deployed. Cross Domain Sync Any process that imports, updates, or reconciles external system data. D Data Freshness How recently a cross domain record was updated relative to its SLA. Data Quality Score A weighted score (0–100) measuring completeness, accuracy, consistency, validity, and freshness. Data Reconciliation The process of validating and correcting cross domain data against the source system. Delta Sync A sync that only processes changed records. Drift Detection Automated detection of schema or data inconsistencies from external systems. Dual Mapping Supporting both old and new external schemas during migration. E ETL (Extract, Transform, Load) A scheduled process that imports external data into PlantSafety. External Contract Test A test validating that an external system’s API or payload matches expectations. External System Any system outside PlantSafety that provides reference data (HRIS, ERP, CMMS, LMS, MES). F Fallback Cache Cached reference data used when an external system is unavailable. Field Mapping The transformation rules that convert external fields into canonical fields. Full Sync A complete refresh of all records from an external system. G Governance (Cross Domain) The policies and review processes that ensure safe, predictable external integrations. Golden Record The authoritative version of a cross domain record after reconciliation. H HRIS (Human Resources Information System) External system providing employee identity and organizational structure. Hybrid Sync A combination of event driven sync and scheduled ETL. I Idempotency (Cross Domain) The guarantee that repeated syncs do not create duplicates or inconsistencies. Integration Hub The central routing, validation, and normalization engine for all cross domain data. Inventory Data ERP provided data describing PPE, materials, or stock levels. L LMS (Learning Management System) External system providing training completions and course metadata. Lookup Table (Cross Domain) A cached table of reference data used for validation and enrichment. M Mapping Drift Unexpected changes in external field values or formats that break mapping rules. MES (Manufacturing Execution System) External system providing production line and WorkCenter activity. Metadata (Cross Domain) Supplemental fields added by PlantSafety, such as SourceSystem or LastSyncedAtUtc . N Normalization The process of converting external data into canonical PlantSafety schemas. Nullability Rule Defines whether a field may be null after mapping. O On Demand Lookup A real time query to an external system via the Integration Hub. Outbound Sync Data sent from PlantSafety to an external system (rare and tightly controlled). P Payload Validation Ensuring external data conforms to canonical schema rules. Primary Source System The external system considered authoritative for a specific data domain. Q Quality Gate (Cross Domain) A validation checkpoint that external data must pass before being accepted. R Rate Limit (External) The maximum number of requests allowed by an external system. Reconciliation Cycle A scheduled process that validates and corrects cross domain data. Reference Data Read only external data used by PlantSafety modules. Retry Envelope Metadata describing retry attempts for external calls. S Schema Drift Unexpected changes in external schemas (fields added, removed, or changed). Schema Mapping The transformation rules that convert external schemas into canonical schemas. SourceSystem Identifier for the external system that provided the data. Sync Latency Time between external system update and PlantSafety ingestion. Sync Throughput Number of records processed per second during cross domain sync. T Tenant Isolation (Cross Domain) Guarantee that external data is tagged and isolated per tenant. Transformation Rule A rule that converts external field values into canonical values. U Upstream System The external system providing data to PlantSafety. Update Frequency How often an external system updates its data. V Validation Error Any failure to meet canonical schema or mapping rules. Version Negotiation Process of determining which external schema version is currently active. W Warm Storage (Cross Domain) Medium term storage for reference data used for reconciliation and analytics. WorkCenter Data ERP/MES provided data describing production areas and operational context. Z Zero Trust (Cross Domain) Security model requiring authentication, authorization, and encryption for all external interactions.
